# 照片转油画棒

把一张有纪念意义的照片转成看起来真的能用手画出来的油画棒作品，并可选地把它重新演绎为一段短循环。相比照片级保真，更重视材料真实感和可绘制化简。

英文版 [`SKILL.md`](../SKILL.md) 是不绑定平台的标准运行入口；本文件是供审查和维护的中文对照版。修改行为时必须保持中英文内容同步。运行条件见 [`requirements.md`](requirements.md)，跨平台接入方式见 [`portability.md`](portability.md)，图像后端接口见 [`backend-contract.md`](backend-contract.md)。`agents/` 下的文件只是可选的平台适配信息，不属于可移植核心的运行依赖。

## 默认交付物

- `01-source.png`：不改动原照片的工作副本。
- `02-final-oil-pastel.png`：完成后的简化油画棒作品。
- `03-early-block-in.png`：大色块铺色阶段。
- `04-late-intermediate.png`：完成度约 75% 的叠色细化阶段。
- `05-process-master.mp4`：本地动画母版。
- `06-oil-pastel-process.gif`：5–10 秒循环 GIF，默认为 6 秒、10 FPS。

如果用户只要静态图，在最终成品完成后停止。用户提到循环、绘画步骤或“从铺色到完成”时，优先生成 GIF；只在用户要求或需要保留高质量母版时附加 MP4。

## 工作流程

### 1. 准备并检查原图

创建独立的输出目录。绝不修改原照片。

如果原图是 HEIC，且图像预览工具无法读取，只转换一份工作副本：

```bash
ffmpeg -y -v error -i SOURCE.HEIC -frames:v 1 OUTPUT_DIR/01-source.png
```

在生成任何内容之前检查转换后的图片，确定：

- 主体或主要结构锚点；
- 一个值得保留的次要视觉锚点；
- 可以删除且不会改变记忆或故事的杂乱元素；
- 6–10 种实际可使用的油画棒颜色；
- 应转化为抽象笔触的文字、招牌、小物件和照片级细节。

当主体包含面部或角色化特征时，生成前必须写一张**特征锁定卡**。只记录画面中可见且影响辨识度的事实：眼睛数量与形状、睁闭方向、瞳孔或高光排列、鼻子几何与填充方式、嘴巴是否存在及其形状、耳朵位置、脸部色斑和固定配饰。把这些硬性特征与允许省略的纹理分开。例如，“两只向下弯的细长眼、各有双高光；实心三角鼻；独立小嘴”属于锁定项，不是可自由变化的风格。

对人像、人物、宠物或纪念物，保留影响辨识度的轮廓、姿势、表情和色块。对风景或街景，保留主要透视、树干、建筑、地平线和灯光位置。

### 2. 规划“可绘制化”

不要直接模仿照片的每一个细节。将原图转换为绘画计划：

- 减少背景物件；
- 将相似颜色合并成大色块；
- 保留一个主焦点，以及最多一个明显的次要锚点；
- 将可读背景文字替换为不可读笔触或简单色块；
- 保留纸张空隙、断裂边缘、不均匀压力和有限叠色；
- 让结果看起来像初级到中级绘画者能用真实油画棒完成。

简化可以删除纹理和次要笔触，但不得重新设计被锁定的五官。未完成阶段可以暂时不画某个细节；一旦画出，就必须保持锁定特征的几何，不能换成另一种符号。

拒绝会产生以下效果的方向：光滑的数字插画、平滑喷枪渐变、过度精细的毛发或花朵、完美矢量边缘、电影式光晕或通用 AI 绘画感。

### 3. 生成最终成品

按以下顺序选择图像编辑后端：

1. 优先使用当前宿主原生支持的图生图或参考图编辑能力；
2. 在 Codex 中，加载并遵循可用的 `imagegen` Skill；
3. 在 API、CLI、Agent 框架或工作流系统中，调用符合 [`backend-contract.md`](backend-contract.md) 的适配器。

将照片视为编辑目标，但不要依赖特定厂商、工具名、SDK 或凭据存放方式。如果当前环境没有兼容的图像编辑后端，则在完成“可绘制化分析”和三段适配后的提示词后停止，明确说明没有生成图片；不得假装生成成功，也不得未经许可安装服务或依赖。

阅读 [`references/prompt-templates.md`](../references/prompt-templates.md)，并根据实际主体调整最终作品提示词。在简化画面的同时保留原始构图，不要引入无关物件或改写故事。

同时对照原图和特征锁定卡检查结果。只在出现实质性失败时重试一次，例如身份特征改变、锁定五官几何改变、解剖结构错误、主体丢失、构图无法辨认、照片细节过多或数字加工感明显。重试时只修正该明确问题。

将确认通过的图片复制到输出目录，命名为 `02-final-oil-pastel.png`。

### 4. 生成两个真实绘画阶段

对两张阶段图，都使用已通过的最终油画棒作品作为参考，而不是原始照片。每个阶段分别生成一张完整分辨率图片，不要生成多格联络表后再切图。

1. **早期铺色：**大面积背景和主体色块，保留大量纸张空隙，五官或物件细节最少，不做抛光。
2. **后期中间阶段：**同一构图约完成 75%，已有阴影和主要细节，但没有最小纹理、尖锐高光、文字或最终边缘整理。

使用 [`references/prompt-templates.md`](../references/prompt-templates.md) 中对应的模板。在每个阶段锁定裁切、透视、主要轮廓、树枝/地平线/建筑位置、主体尺寸，以及手部或面部几何。

把同一张特征锁定卡原文放入两个阶段提示词。如果面部在全图中很小，而图像后端支持遮罩、局部裁切/参考控制或局部修正，则优先保护该区域。缺少细小纹理可以接受；眼睛、鼻子或嘴巴的结构不同不能接受。

主要锚点跳动或任一锁定特征变化时，对该阶段定向重试一次。如果修正后的阶段仍违反特征锁定，则拒绝该阶段并停止合成 GIF；应如实报告阶段未通过，不得把身份漂移解释成手绘差异。

### 5. 组装循环

使用内置脚本。它需要 `ffmpeg` 和 `ffprobe`，但不需要第三方 Python 包：

```bash
python3 scripts/assemble_step_loop.py \
  --early OUTPUT_DIR/03-early-block-in.png \
  --middle OUTPUT_DIR/04-late-intermediate.png \
  --final OUTPUT_DIR/02-final-oil-pastel.png \
  --output OUTPUT_DIR/06-oil-pastel-process.gif \
  --keep-master OUTPUT_DIR/05-process-master.mp4 \
  --duration 6 \
  --fps 10
```

循环使用直接阶段变化，不使用“模糊到清晰”、像素揭示、横向条带遮罩、几何溶解或其他会让结果看起来像 AI 滤镜的效果。最终阶段的停留时间最长。

### 6. 验证

- 比较原图和最终作品：记忆、主体和构图必须仍可辨认。
- 并排比较三张生成阶段：主要锚点不应移动或改变尺寸。
- 以足够倍率检查每个影响身份的面部或角色区域。对照特征锁定卡检查眼睛几何和高光排列、鼻子几何、嘴巴是否存在及其形状、耳朵、色斑和固定配饰。
- 未完成阶段可以少画笔触，但每个已经出现的锁定笔触必须与定稿保持相同结构和相对位置。圆眼替换弧形眼、Y 形鼻替换三角鼻，或嘴巴已经建立后又消失，都必须判定为失败。
- 确认早期和中间帧本身是合理的未完成作品。
- 确认 GIF 时长为 5–10 秒，且最终作品停留足够长。
- 检查开始、中间和最终帧。拒绝解剖结构变形、多余肢体、建筑移动、树干偏移、虚构可读文字或数字遮罩伪影。
- 紧凑的竖版 GIF 优先使用 540×720、10 FPS。需要减小文件时，先降低 GIF 宽度或帧率，不要先缩短时长。

## Token 与用量报告

每次最终回复都必须包含用量区块：

- 成功的图像生成调用次数；
- 失败或取消的图像生成调用次数（如果存在）；
- 当选定工具返回 Token 用量时，报告准确的输入、输出/图像和总 Token；
- 对工具未暴露的每个 Token 字段填写 `unavailable`，并简述原因；
- 绝不估算或编造 Token 数字；
- 说明本地 FFmpeg 合成本身不会调用图像生成模型。

## 边界

- 将 GIF 描述为根据生成的绘画阶段进行的分阶段重演，而不是模型隐藏生成历史或真实画家录像。
- 显示一只手真正绘制每一笔，属于不同的视频生成或合成流程。除非已具备所需能力或用户提供了素材，否则不得承诺。
- 除非用户明确要求保留精确文字且已验证结果，否则不保留或虚构可读招牌。
- 没有明确授权时，不删除其他艺术家的签名或水印。

## 可移植性

- 复制 Skill 时保留完整目录结构，确保相对链接和合成脚本仍能使用。
- 模型选择、服务商凭据和密钥必须放在宿主平台或适配器中，不写入本 Skill。
- 非 OpenAI 平台可以忽略 `agents/openai.yaml`；它只提供可选的 OpenAI/Codex 发现信息。
- 如果环境没有 FFmpeg，则交付三张静态阶段图，并说明跳过了本地 GIF/MP4 合成。
- 其他平台的安装和接入模式见 [`portability.md`](portability.md)。
